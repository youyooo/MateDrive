# MateDrive iPhone 小组件与灵动岛本地增强设计

**日期：** 2026-08-10
**状态：** 产品设计与书面规格已确认，进入实施计划复核
**产品：** MateDrive iOS
**方案：** A — 本地原生增强

## 目标

在不增加服务器推送系统、不接触车辆控制能力的前提下，完善 MateDrive 已有的 iPhone 主屏幕小组件、锁屏实时活动和灵动岛体验。用户应能在手机原生入口可信地看到当前充电状态，并从车辆状态、充电趋势和电池趋势小组件进入正确的 App 页面。

本设计优先解决四个问题：

1. 当前没有独立的“当前充电”主屏幕小组件；
2. 充电实时活动的启动与更新目前集中在“当前充电”页面；
3. 灵动岛和锁屏实时活动仍有未本地化文案；
4. 离线、部分数据和过期数据缺少统一、明确的可信度表达。

## 已有基础

当前工程已经包含：

- 可按车辆配置的车辆状态小组件；
- 电池趋势和 30 天充电趋势小组件；
- 充电锁屏实时活动与灵动岛的最小、紧凑和展开形态；
- App Group 中按服务器和车辆隔离的匿名快照；
- 后台预加载和 WidgetKit 时间线刷新；
- Dashboard、Current Charge、Charges、Battery 等现有 App 路由；
- 简体中文、繁体中文、英文和公制、英制显示能力。

本迭代复用这些基础，不建立第二套缓存、路由或同步系统。

## 范围

### 本轮包含

- 新增一个可按车辆配置的“当前充电”小组件；
- 支持 `.systemSmall` 和 `.systemMedium`；
- 补齐现有四类原生入口的可信跳转；
- 将灵动岛启动、更新、结束策略收口到独立协调层；
- App 在前台确认充电时允许启动实时活动；
- 后台同步仅更新或结束已经存在的实时活动；
- 对充电中、准备充电、未充电、离线、部分数据、过期和无数据建立统一状态；
- 补齐实时活动的三语文案、数据时间和无障碍语义；
- 增加单元、集成、界面、隐私和发布回归门禁。

### 本轮不包含

- 锁车、解锁、空调、充电口或其他车辆控制；
- APNs、ActivityKit push-to-start、远程推送令牌和新加坡服务器任务；
- 小组件扩展直接访问 TeslaMate 或读取认证凭据；
- `.systemLarge`、锁屏 accessory 小组件、Apple Watch 或 CarPlay 专用布局；
- 精确位置、地址、VIN、服务器地址或认证信息进入新的充电小组件或实时活动；
- 承诺后台分钟级实时刷新；
- 上传 TestFlight、安装真机或提交审核。

真正无需打开 App 的自动启动与持续更新保留在候选想法池，未来必须以独立的 APNs、隐私和服务器可靠性设计推进。

## 用户体验

### 当前充电小组件：小号

小号小组件优先回答“现在充到多少、还要多久”：

- 车辆名称；
- 当前电量；
- 目标电量；
- 当前充电功率；
- 预计完成时间；
- 充电、准备充电、未充电、离线或过期状态。

空间不足时，电量和状态优先于功率和预计时间。缺失字段显示 `--` 或从布局中省略，不得显示为零。

### 当前充电小组件：中号

中号小组件增加：

- AC 或 DC 类型；
- 本次已充电量；
- 当前电量到目标电量的进度；
- 最近成功更新时间；
- 离线、部分数据或过期说明。

### 现有小组件

- 车辆状态小组件保持现有小号和中号布局，点击进入 Dashboard；
- 电池趋势小组件点击进入 Battery；
- 充电趋势小组件点击进入 Charges；
- 现有车辆选择方式、趋势计算和隐私规则保持不变。

### 灵动岛与锁屏实时活动

- 最小形态显示充电图标；
- 紧凑形态显示充电图标和电量；
- 展开形态显示车辆、电量、目标、功率和进度；
- 锁屏形态增加已充电量、预计时间和明确的数据可信度；
- 所有文案跟随 App 的简体中文、繁体中文或英文设置；
- 点击实时活动进入对应车辆的 Current Charge 页面。

不增加控制按钮。原生入口只展示数据和打开 App。

## 状态模型

新增可向后兼容的可选数据结构：

```swift
enum WidgetChargePhase: String, Codable {
    case charging
    case starting
    case idle
}

enum WidgetChargeDataQuality: String, Codable {
    case complete
    case partial
    case offline
}

struct WidgetCurrentChargeData: Codable, Equatable, Sendable {
    let phase: WidgetChargePhase
    let quality: WidgetChargeDataQuality
    let batteryLevel: Int?
    let chargeLimitSoc: Int?
    let chargerPowerKW: Int?
    let energyAddedKWh: Double?
    let timeToFullMinutes: Int?
    let isDC: Bool?
    let updatedAt: Date
}
```

`WidgetVehicleSnapshot` 增加可选的 `currentCharge`。旧快照缺少该字段时继续正常解码，并显示“打开 MateDrive 完成同步”，不得导致整个车辆快照失效。

当前充电数据复用父级 `WidgetDisplayData` 已保存的语言和单位设置，不在子结构中建立第二份可能失配的偏好副本。

### 状态判定

| 输入结果 | 小组件状态 | 实时活动行为 |
| --- | --- | --- |
| 车辆状态确认充电，当前充电详情成功 | `charging / complete` | 前台可启动或更新；后台仅更新已有活动 |
| 车辆状态确认充电，接口明确没有活动记录 | `starting / complete` | 前台可启动或更新准备状态 |
| 车辆状态确认充电，详情请求失败 | `charging / partial` | 保留已有活动并标记部分数据，不结束 |
| 车辆状态明确未充电 | `idle / complete` | 清空旧充电指标并结束活动 |
| 车辆状态请求失败 | 保留上次内容并改为 `offline` | 不启动、不结束；已有活动保持到恢复或系统过期 |
| 没有任何快照 | 无数据引导 | 不创建活动 |

一次失败不得被解释成“已经停止充电”。只有权威状态明确返回未充电时，才能结束实时活动。

### 新鲜度

- `updatedAt` 表示最近一次权威成功结果，不在失败时伪造更新；
- 主屏幕小组件在 30 分钟内显示正常状态；超过 30 分钟显示“数据可能已过期”及更新时间；
- `offline` 无论时间长短都显示离线；
- 实时活动继续使用两分钟 `staleDate`；进入 stale 状态后显示“待更新”并弱化动态指标；
- 恢复成功后清除离线或过期提示。

## 数据流

### 前台

1. Dashboard 或 Current Charge 获得车辆状态；
2. 纯数据构建器生成 `WidgetCurrentChargeData`；
3. `WidgetSnapshotStore` 将状态与现有车辆、趋势数据合并后写入 App Group；
4. WidgetKit 只重载受影响的时间线；
5. 实时活动协调器使用 `allowStart` 策略进行启动、更新或结束。

### 后台

1. 现有后台同步正常读取车辆状态；
2. 只有状态明确为正在充电时，才额外请求该车辆的当前充电详情；
3. 快照按成功、部分成功或失败合并，失败不覆盖最后成功内容；
4. WidgetKit 重载受影响时间线；
5. 实时活动协调器使用 `existingOnly` 策略，只更新或结束已经存在的活动。

小组件扩展永远不执行网络请求，也不读取 Keychain。

## 组件边界

### `WidgetCurrentChargeData`

只表达可显示的当前充电状态。它不负责请求、缓存、格式化页面或控制 ActivityKit。

### `CurrentChargeWidget`

只读取配置车辆的共享快照并渲染小号、中号布局。它不判断服务器错误，也不访问认证信息。

### `WidgetCurrentChargeSnapshotBuilder`

将车辆状态、当前充电结果、语言和单位转换成稳定的显示模型。所有状态判定均由纯函数完成，以便独立测试。

### `ChargeLiveActivityCoordinator`

接收三类明确结果：充电快照、权威未充电、无法确定。协调器根据前台或后台策略决定启动、更新、结束或不操作；它不发起 TeslaMate 请求。

### `SystemChargeLiveActivityManager`

继续封装 ActivityKit，但将“启动或更新”和“仅更新已有活动”分开，避免后台路径错误尝试创建新活动。

### `WidgetNavigationRouter`

负责构建、解析和验证原生入口跳转。它只接受白名单目标和匿名车辆标识，不接受任意 URL、服务器地址或原始车辆编号。

## 跳转设计

使用受控的 MateDrive URL 路由，例如：

`matedrive://widget/current-charge?vehicle=<opaque-vehicle-id>`

允许的目标只有：

- `dashboard`；
- `current-charge`；
- `battery`；
- `charges`。

匿名车辆标识继续由规范化服务器来源和车辆编号单向散列生成。App 收到跳转后，使用当前服务器和已知车辆重新计算标识并匹配真实 `carId`，不在 URL 中传递原始服务器或车辆编号。

匹配失败时：

1. 未配置 App 进入 Settings；
2. 已配置但车辆无法匹配时回退到最近选择车辆；
3. 没有可用车辆时进入 Dashboard。

未知 scheme、未知目标、超长参数或多余敏感参数直接拒绝，不影响当前导航状态。

## 实时活动生命周期

协调器使用两个激活策略：

- `allowStart`：只在 App 处于前台活跃状态时使用，可创建或更新活动；
- `existingOnly`：后台同步使用，只更新或结束现有活动，不创建活动。

生命周期规则：

- 同一车辆最多保留一个充电实时活动；
- 多辆车可按各自匿名标识和 `carId` 隔离；
- `ChargeLiveActivityAttributes` 保存用于跳转的匿名车辆标识，绝不保存服务器地址；
- Activity 内容状态携带显示语言，使已有活动在下一次更新时同步 App 的语言选择；
- 充电中重复刷新只更新现有活动；
- 单次请求失败不结束活动；
- 权威未充电结束对应车辆活动并立即移除；
- App 更新后的旧活动若无法按新内容解码，应安全结束，不影响 App 启动；
- 不记录 ActivityKit 错误中的服务器或认证信息。

本地方案不能保证 App 从未打开时自动启动灵动岛。此限制必须在产品文案和验收中保持诚实，不以后台刷新计划冒充实时推送。

## 本地化、单位与无障碍

- 新文案加入 String Catalog，并编译到 App 与 Widget 扩展；
- 支持简体中文、繁体中文和英文，不保留 `AC Charging`、`Battery`、`Limit`、`h`、`m` 等硬编码英文；
- 距离和温度继续跟随现有单位设置；功率使用 kW，能量使用 kWh；
- 时间长度通过统一格式化器生成本地化文本；
- 装饰图标对 VoiceOver 隐藏，组合指标提供完整标签和值；
- 小组件支持大字体、高对比度、浅色和深色；
- 长车辆名称必须截断而不挤压关键电量和状态；
- 本轮只对列出的原生入口和状态作无障碍验收，不宣称整个 App 已完全符合所有无障碍标准。

## 隐私与安全

- 新充电小组件和实时活动不显示精确位置或地址；
- App Group 快照不得写入 Token、Basic Auth、服务器 URL、VIN或原始认证头；
- 跳转只携带不可逆匿名车辆标识；
- 小组件扩展不拥有网络客户端或 Keychain 访问路径；
- 失败状态只保存枚举，不保存原始错误正文；
- 清除 Widget 快照时同时清除当前充电数据并重载所有时间线；
- 现有 App Group 和数据保护策略保持不变。

## 性能边界

- 未充电车辆不增加当前充电详情请求；
- 每次同步对每辆确认正在充电的车辆最多增加一次当前充电详情请求；
- 不增加常驻轮询任务；
- 小组件时间线继续依赖 App 写入的快照，不自行提高刷新频率；
- 只重载数据发生变化的小组件 kind，清除全部缓存等全局事件除外；
- Widget 快照大小保持有界，趋势样本数量维持现有上限。

## 错误处理

- 当前充电详情失败但车辆状态成功时，显示部分数据，不影响车辆状态；
- 车辆状态失败时保留最后成功内容并显示离线；
- 数据字段缺失时省略或显示 `--`，不得替换为零；
- 无配置或无快照时提供打开 App 的恢复入口；
- 损坏快照按无数据处理，不让 Widget 扩展崩溃；
- 无法创建实时活动时保留主屏幕小组件，不向用户显示底层 ActivityKit 错误；
- 非法跳转不改变当前路由。

## 完成标准

本功能只有在以下条件全部满足时才算完成：

1. 新的当前充电小组件覆盖小号和中号；
2. 四类小组件和实时活动都能进入正确页面；
3. 前台能够在确认充电后创建或更新实时活动；
4. 后台不会创建新活动，但能安全更新或结束已有活动；
5. 离线和过期数据不会伪装成实时数据；
6. 不引入服务器推送、车辆控制或敏感信息暴露；
7. 聚焦、完整和发布门禁全部通过；
8. 发布候选在获得授权后通过 TestFlight 真机充电闭环。
