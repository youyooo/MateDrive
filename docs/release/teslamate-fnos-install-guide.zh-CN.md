# TeslaMate 飞牛 FPK 安装与首次配置指南

适用版本：`App.Native.TeslaMate 0.1.2`（x86/x86_64 飞牛 NAS）

这是一个未签名的第三方 FPK，安装时飞牛会显示“未经验证应用”的安全提示。包内包含官方 TeslaMate、PostgreSQL、Grafana、Mosquitto，以及为手机客户端保留的第三方 TeslaMateAPI；TeslaMateAPI 不是 Tesla 官方组件。

## 一、安装前准备

安装前请确认：

- 飞牛 NAS 为 x86/x86_64 架构，已启用 Docker，至少有 10 GB 可用空间。
- NAS 局域网地址可以被手机或电脑访问。
- 端口 `14000`、`14001`、`3030` 没有被其他应用占用。
- 默认容器网段 `10.253.0.0/24` 没有与家庭网络、VPN 或 NAS 其他容器网络冲突。
- 已在密码管理器中准备四项独立凭据。安装包不提供默认密码，也不会把凭据写入包内。

凭据格式如下：

| 向导字段 | 用途 | 要求 |
| --- | --- | --- |
| `DATABASE_PASS` | PostgreSQL 数据库密码 | 24–128 位，仅字母和数字 |
| `ENCRYPTION_KEY` | TeslaMate Token 加密密钥 | 32–128 位，仅字母和数字 |
| `GRAFANA_PW` | Grafana 管理员密码 | 16–128 位，仅字母和数字 |
| `API_TOKEN` | 手机 API 访问令牌 | 32–128 位，仅字母和数字 |

不要把 API Token 发到群聊、截图或公网 URL 中。三个网页端口只建议在家庭局域网使用，不要直接在路由器上做端口转发。

## 二、在飞牛应用中心安装

1. 准备文件 `App.Native.TeslaMate_0.1.2_x86_fnpack.fpk`。
2. 打开“应用中心”，进入“手动安装”，选择安装存储空间。
3. 点击“从电脑上传”，选择 FPK 文件。
4. 飞牛显示“未经验证应用”的提示时，确认发布者和文件来源无误后选择“同意”。
5. 在“网络与地区”页填写或保留默认值：
   - TeslaMate 网页端口：`14000`
   - Grafana 网页端口：`14001`
   - TeslaMateAPI 端口：`3030`
   - 容器网络 CIDR：`10.253.0.0/24`
   - 时区：`Asia/Shanghai`
6. 在“安全凭据”页分别填入四项凭据。四个密码框必须填不同的值，不能留空；`API_TOKEN` 是手机连接用的令牌，建议直接使用密码管理器的随机密码功能生成后粘贴；输入错误时按页面提示修正。
7. 提交安装并等待应用中心完成 Compose 创建和镜像下载。
8. 首次安装会下载数 GB 镜像，页面可能较长时间显示“安装中”。只要下载仍有流量或应用中心进度在变化，就不要重复点击安装或强制卸载。
9. 安装完成后，应用中心中的 TeslaMate 状态应为“打开”。如果状态仍是“启用”，先点击“启用”，等待服务启动完成。

### 已有 0.1.0/0.1.1 安装的升级

直接在应用中心上传 `0.1.2` 即可执行升级。升级会重建容器，但保留以下命名卷：

- `teslamate-fnos_teslamate-db`
- `teslamate-fnos_teslamate-grafana-data`
- `teslamate-fnos_teslamate-import`
- `teslamate-fnos_mosquitto-conf`
- `teslamate-fnos_mosquitto-data`

如果升级或重装时输入了新的数据库密码，0.1.2 会先在 PostgreSQL 通过健康检查前同步 `teslamate` 角色密码，再启动其他服务；不需要手工执行 SQL，也不会删除数据库卷。

## 三、安装完成后的访问

安装完成后，飞牛桌面会显示 TeslaMate、Grafana、手机 API 三个入口；也可以将 `NAS_IP` 替换为飞牛 NAS 的局域网地址直接访问：

- TeslaMate：`http://NAS_IP:14000/`
- Grafana：`http://NAS_IP:14001/`，管理员用户名为 `admin`，密码是安装时填写的 `GRAFANA_PW`。
- TeslaMateAPI：`http://NAS_IP:3030/`，手机客户端使用安装时的 `API_TOKEN`。

如果在向导中修改了端口，以应用中心配置页当前保存的端口为准；桌面入口会自动跟随配置。Grafana 已经包含在本 FPK 内，不需要再从飞牛商店单独安装一个 Grafana 实例，否则会产生重复服务和端口冲突。

手机 API 请求必须使用 Bearer Token，例如请求 `/api/v1/cars` 时携带：

```http
Authorization: Bearer <API_TOKEN>
```

安装时请把 `API_TOKEN` 保存到密码管理器；TeslaMateAPI 不会在首页明文展示令牌。如果令牌遗失，进入飞牛应用中心的配置页，重新生成一串符合规则的随机值并保存，然后在手机 App 中同步更新令牌。

PostgreSQL 和 MQTT 只在 Compose 内部网络提供服务，不开放 NAS 宿主端口。

TeslaMate 首次打开后，需要由安装者在 TeslaMate 页面自行完成 Tesla 登录。这个 FPK 不会自动导入 Tesla 账号、车辆、历史行程或旧 Token。

## 四、修改配置

在应用中心打开 TeslaMate 的配置页：

- 修改端口前，先确认新端口未被占用。
- 修改容器网段前，先确认新网段未与现有家庭网络、VPN 或 Docker 网络重叠。
- 修改凭据后保存，飞牛会重建服务；五个命名卷不会被主动删除。
- 轮换数据库密码时，保存新密码，等待数据库健康后再测试 TeslaMate 和 API；不要同时删除数据库卷。

## 五、常见问题

| 现象 | 处理方式 |
| --- | --- |
| 一直显示“安装中” | 首次下载较大，先确认应用中心仍有下载流量、NAS 空间不少于 10 GB；不要重复安装。 |
| 安装提示端口冲突 | 换用未占用的端口，并用新的端口访问对应页面。 |
| 提示容器网段冲突 | 将 `DOCKER_SUBNET` 改成未使用的私有网段，例如 `10.254.0.0/24`。 |
| 手机 API 返回 `401` | 检查客户端是否发送 `Authorization: Bearer <API_TOKEN>`，并确认 Token 与应用配置一致。 |
| TeslaMate 页面跳转到登录页 | 这是正常行为，先在 TeslaMate 页面完成 Tesla 登录。 |
| 页面能打开但没有今天的数据 | 尚未完成 Tesla 登录、车辆尚未授权，或当前仍是空数据安装；先检查 TeslaMate 登录状态。 |
| 修改数据库密码后服务未恢复 | 确认密码满足格式要求，等待 PostgreSQL 显示健康；0.1.2 会自动同步保留卷密码，不要手工删卷。 |

## 六、卸载与数据边界

普通卸载会移除应用容器和应用文件，但默认保留命名卷。需要保留数据时，不要在 Docker 或文件管理器中删除 `teslamate-fnos_*` 卷。个人 Tesla 登录、历史数据迁移、新加坡服务器转发和手机生产环境切换不属于本次安装流程。
