# 行程历史天气与驾驶环境设计

## 目标

行程详情只查询一次能代表该行程的历史天气。只有查询或本地缓存命中成功结果时才展示“驾驶环境”；没有时间、没有有效坐标、请求失败或返回数据不完整时都隐藏该模块。V1 不展示沿途多点天气、逐点列表或天气曲线。

## 数据选择

- 从行程位置记录中筛掉无效经纬度、缺少时间或时间无法解析的样本。
- 以首尾有效样本的时间中点为目标，选取时间最接近的一个 GPS 样本；只有一个有效样本时直接使用它。
- 用该样本的经纬度和时间调用 Open-Meteo Historical Forecast API，并选取最接近行程样本时刻的小时数据。
- 请求温度、天气代码、10 米风速、10 米风向、降水量和能见度。缺少可选字段不影响温度与天气状况展示；温度或天气代码缺失时视为无结果。

## 本地缓存

- 历史天气成功结果写入 Application Support 下的独立 JSON 文件。
- 缓存键由四位小数精度的经纬度和 UTC 小时时间戳组成；相同位置与小时直接复用结果，不再次访问网络。
- 历史结果不设置时间过期，因为已发生时刻的天气不会再变化；缓存设置条目上限并按保存时间淘汰最旧记录。
- 失败结果不缓存，确保临时网络或服务故障后仍可重试。

## UI 与状态

- `DriveDetailState` 保存单个可选驾驶环境天气，不再保存沿途天气数组。
- 加载期间不显示占位卡；成功后展示“驾驶环境”卡，失败或无数据时完全不插入该视图。
- 卡片展示天气状况与温度，并在字段存在时展示风、降水和能见度。
- 行程表现、智能通勤、个人标定、车辆概览、最低能耗氛围及其他行程卡片保持原有顺序与行为。

## 错误处理与隐私

- 天气失败不影响行程详情主请求，也不复用行程详情错误提示。
- 只向 Open-Meteo 发送一个代表样本的坐标与日期，不发送整条轨迹。
- 不记录原始坐标、认证信息或天气请求正文到日志。

## 验证

- 单元测试覆盖代表样本选择、历史小时映射、成功缓存持久化、缓存命中不重复请求、失败隐藏和成功展示状态。
- 运行相关定向测试、完整 XCTest、发布前脚本与模拟器安装启动验证。
- 构建号递增后生成签名归档、审计归档并上传 TestFlight，记录 Apple 返回的上传状态。
